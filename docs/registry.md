# Component Registry

This repo publishes its components, hooks, utilities and theme as a
self-hosted [shadcn registry](https://ui.shadcn.com/docs/registry), so other
projects can install them with the shadcn CLI. The registry is generated by
[`scripts/generate-registry.mjs`](../scripts/generate-registry.mjs) and
deployed to GitHub Pages by
[`.github/workflows/deploy-registry.yml`](../.github/workflows/deploy-registry.yml)
at `https://dosepehr.github.io/frontend-foundation/r/`.

## Installing into another project

```bash
# in the other project, if it's not already a shadcn project:
npx shadcn init

# install everything:
npx shadcn add https://dosepehr.github.io/frontend-foundation/r/index.json

# or a single item:
npx shadcn add https://dosepehr.github.io/frontend-foundation/r/button.json
```

## Where files land in the consuming project

Every item's target is relative to one of the consumer's `components.json`
aliases, and the shadcn CLI rewrites the imports inside each file
(`@/components/ui`, `@/components`, `@/lib`, `@/hooks`) to those aliases. So
the consumer's `components.json` alone decides the layout.

For a project on the standard feature-based layout (`src/shared/…`), set:

```json
{
    "aliases": {
        "components": "@/shared",
        "ui": "@/shared/ui",
        "hooks": "@/shared/hooks",
        "lib": "@/shared/lib",
        "utils": "@/shared/lib/utils"
    }
}
```

| Source in this repo                  | Item type            | Lands in (with the aliases above) |
| ------------------------------------ | -------------------- | --------------------------------- |
| `src/components/ui/<Name>/`          | `registry:ui`        | `src/shared/ui/<Name>/`           |
| `src/components/controlled/<Name>/`  | `registry:ui`        | `src/shared/controlled/<Name>/`   |
| `src/components/providers/<Name>/`   | `registry:component` | `src/shared/providers/<Name>/`    |
| `src/utils/hooks/<useName>/index.ts` | `registry:hook`      | `src/shared/hooks/<useName>.ts`   |
| `src/utils/{funcs,api,store,env}/…`  | `registry:lib`       | `src/shared/lib/…` (same subpath) |
| `src/app/globals.css` tokens         | `registry:theme`     | the consumer's CSS file           |

Published providers: `AppleSplashScreens`, `OfflineMutationSync` (required by
`react-query-provider`), `ReactQueryProvider` and `ServiceWorkerRegister`. `MockProvider` is
dev-only and not published.

## Rebuilding

```bash
npm run registry:build    # writes public/r/*.json (gitignored)
```

`npm run build` runs it too. Set `REGISTRY_BASE_URL` to the URL the registry
will be served from — every `registryDependencies` entry is a full URL into
this registry, because bare names resolve against ui.shadcn.com. CI sets it
to the GitHub Pages URL.

Re-run after changing any component, hook, util or token. Never hand-edit the
generated JSON. Test files (`*.test.*`, `*.spec.*`) and stories are excluded
automatically.

## Adding a new publishable file

- **UI / controlled component** — add a folder under `src/components/ui/` or
  `src/components/controlled/`; it is picked up automatically.
- **Hook** — add `src/utils/hooks/<useName>/index.ts`; picked up
  automatically.
- **Provider** — add the folder name to the providers list in the generator.
- **Lib file** — add an entry to `LIB_FILES` in the generator.

The build fails with `Unmapped internal import` when a published file
imports something that isn't published. Publish the dependency too, or remove
the import.
